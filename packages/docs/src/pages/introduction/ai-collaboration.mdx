# 与 AI 协作（Agent-ready）

本工程从架构设计之初就确立了「人机同席」的开发范式：既为人写，也为 AI 助手（Claude Code、Cursor、Windsurf 等）建立了低混淆、可自动判定的工程边界。

## 复制即用的 AI 初始化 Prompt

将以下内容放入 Cursor Rules (`.cursorrules`)、Claude 记忆或直接在对话开头投喂给 AI 助手：

```text
你正在一个严格分层的生产级 Electron Monorepo 项目中协作。请恪守以下工程铁律：
1. 先读根目录 AGENTS.md 以及你将要修改包内的 AGENTS.md（如 packages/main/AGENTS.md）。
2. 架构单一真源：类型与 IPC 契约必须在 @app/shared 统一定义，严禁在 main/renderer 端私造重复契约。
3. 严格禁止桶文件（Barrel Files）与 export *，严禁新增双导出反模式（默认导出与具名导出混用）。
4. 根目录 package.json 的 dependencies 只允许 @app/main，业务依赖必须装入对应子包。
5. 提交代码前，必须确保 pnpm typecheck && pnpm lint && pnpm test 全部通过。
```

## 三层 AI 协作防御体系

```
       [Prompt / 上下文注入]  ──> 根目录 & 各包 AGENTS.md（引导意图）
                 │
       [架构契约单向流动]    ──> @app/shared 集中管理契约与 Zod Schema（防止漂移）
                 │
       [硬性门禁静态拦截]    ──> Biome 规则 + verify:prebuild + Commitlint（物理报错）
```

### 1. 分层规约定位（AGENTS.md）

- **全局总则**（[根目录 AGENTS.md](https://github.com/BanShan-Alec/electron-react-monorepo-template/blob/main/AGENTS.md)）：定义全局红线（根依赖限制、禁桶文件、ESM 全包约定）、包索引路由与通用命令。
- **子包细则**（各子包内的 `AGENTS.md`）：如 `@app/main` 的 Controller/Service 分层与异步释放规范，`@app/renderer` 的 Feature 驱动与中文优先 i18n 规范。

### 2. 工具拦截胜过千言万语（物理门禁）

不要试图靠自然语言提示词让 AI 100% 遵守规范，工程内已部署硬性拦截器：

- **禁止桶文件与循环导入**：Biome 规则直接配置 `noBarrelFile: "error"` 与 `noImportCycles: "error"`。
- **根依赖防污染**：`pnpm verify:prebuild` 校验根目录 `dependencies`，任何误装立即中断构建。
- **中文 Conventional Commits**：Commitlint 自定义插件校验提交必须带有中文字符，保障变更历史可读性。

### 3. AI 评审与自动化闭环

工程内置了 `@app/pr-review` 评审联动工具链。当提交 PR 或请求审查时，可通过一键命令拉取远程 OCR 评审建议并指导 AI 修复：

```bash
pnpm pr-review pull      # 拉取最新远程评审评论到本地
pnpm pr-review status    # 查看未解决的问题列表
pnpm pr-review merge     # 校验通过后自动执行合流
```

详细工作流见 [AI 评审闭环（Open-code-review）](/ai/review-loop)。
