# AI 协作者约定（Agents.md）

> **TL;DR**：建立基于「七维度设计准则」的根/包级 `AGENTS.md` 体系：根目录收敛全局红线与任务路由，子包 `AGENTS.md` 负责包级规则入口和日常约束，专项细则由其明确链接的文档承载。让 AI 助手按需加载相关规则，减少重复维护与漂移。

## 1. 选型理由

- **注意力经济与抑制幻觉**：AI 上下文窗口随多轮对话线性损耗，堆砌低信息密度的静态目录树或平铺脚本，是引发逆向依赖与逻辑幻觉的温床。
- **单一真源与杜绝漂移**：大型 Monorepo 规则若散落于各包 README 或由人肉口头传达，规则必然漂移失效。各包 `AGENTS.md` 随 `cwd` 就近自动注入，提供局部规则入口；较长或按文件 / 任务触发的细则由入口明确链接到专项文档，避免全量注入和重复维护。
- **机器可判定性（Machine-verifiable）**：可机械判定的约束绑定编译器、Biome 或 CI 门禁；其余语义规则与任务流程以有范围、可路由的代理指引承载，不将提示误称为硬门禁。

## 2. 核心架构与七维度设计规范

全仓规则治理严格对齐业界标杆的七个核心维度：

| 维度                    | 核心法则                                       | 本仓库治理实践                                                                     |
| :---------------------- | :--------------------------------------------- | :--------------------------------------------------------------------------------- |
| **1. 注意力经济**       | 篇幅严格 `<150 行`，杜绝长文                   | 保留路由入口与必要代码骨架；长细则按文件或任务按需引用，避免静态目录树与重复抄录   |
| **2. 单向流动**         | 依赖方向与可见性严格单向                       | 遵循 `entries ➔ features ➔ 跨域层`，域间禁止互引，Service 零 IPC 感知              |
| **3. Pattern Matching** | 提供完整具象的合法代码骨架                     | 拒绝单行压缩面条代码，提供带完整 `import` 的 Service / Controller / 七段式组件模板 |
| **4. 负面约束与豁免**   | 固化踩坑经验与反模式清单                       | 明示关键豁免与安全边界；具体规则由对应包级入口指向唯一真源                         |
| **5. 孤岛单测判据**     | 杜绝单测被全仓过滤导致的漏测                   | 独立包在包级规则中声明专用测试门禁，避免误判全仓测试覆盖                           |
| **6. 机器门禁矩阵**     | 场景化组合命令取代平铺罗列                     | 根规则提供日常闭环、PR 提交前全量、发版预检等精准机器判据矩阵                      |
| **7. 单一真源**         | 根做全仓路由，包级 AGENTS 是入口和日常规则真源 | 文档站只讲架构动机；契约与导出边界以根 / 包级规则真源为准                          |

→ 根规则源码：[AGENTS.md](https://github.com/BanShan-Alec/electron-react-monorepo-template/blob/main/AGENTS.md) · 包级规则入口：`packages/<pkg>/AGENTS.md`；专项细则由入口明确链接的文档承载

本页说明规则如何组织，而不是业务规则本身。配置、源码和任务门禁的具体内容仍以各自真源为准，本文只解释治理原则并提供入口。

## 3. 桌面端避坑注意事项

| 避坑要点                  | 事故表现与原因                                                          | 本仓库对齐方案                                       |
| :------------------------ | :---------------------------------------------------------------------- | :--------------------------------------------------- |
| **伪代码或边界遗漏**      | 机械压缩行数导致 SOP 丢失 `import` 与分行；漏掉架构豁免也可能引发递归。 | 示例保留必要流程；具体架构约束以对应包级规则为准。   |
| **独立测试入口漏跑**      | 根测试套件可能不覆盖每个独立包，误判全绿会漏掉测试。                    | 对应包规则声明专用测试门禁；命令只维护在单一真源。   |
| **Renderer 原生能力越界** | 渲染层直接访问系统能力可能破坏隔离边界并导致运行时故障。                | 通过 Preload 暴露必要能力；细则由根 / 包级规则指引。 |
