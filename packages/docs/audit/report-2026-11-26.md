### 3.2 系统性结论

1. **正文达标率几乎为零**：44 页里绝大多数「正文」（剔除代码块 / 表格 / 空行）只有 20–30 行，达不到机制页 40 行下限。这不是逐页懒，而是口径未定义（见 §6 R6）——同一批页按总行数看大多在 60–160 行，按非空正文看全部偏低。**不应用逐页补字解决。**
2. **代码块普遍超长**：约 35 页存在 >15 行的单块；极值 `artifact-smoke` 86 行、`release-pipeline` 68 行、`error-boundary` 33/23/35 行、`window-state` 37 行、`module-lifecycle` 37/35 行。共同成因是把函数体 / 组件 / 整个 workflow 搬进页面。
3. **「本页负责 / 不负责」声明几乎全缺**：44 页里只有 `config-persistence`、`design-tokens`、`theme-pipeline`、`first-screen`、`antd` 少数几页写了边界；这也直接导致 8 组同题页互不知道对方存在。
4. **全站零第三方官方直链**：`electronjs.org` / `developer.mozilla.org` / `ant.design` / `lingui.dev` / `vitest.dev` / `typescriptlang.org` 在所有 60 页中命中数为 0。D2b 的结论不是「某几页缺链接」，而是**全站没有这个习惯**。
5. **代码块失真率惊人**：44 页中至少 31 处代码块属于「臆造」「改写后冒充真实摘录」或「整函数照搬」，其中 3 处会直接让读者抄出**跑不通的代码**（见 §5.1）。
