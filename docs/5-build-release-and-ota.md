# 阶段五：打包构建、签名与增量热更

本文档指导你如何执行客户端打包、配置代码签名，以及实现 OTA 自动检查与升级。

## 1. 解决什么问题

在桌面应用发布阶段，开发者经常遇到这三个问题：
- 打包配置文件冗长难维护，打包体积动辄几百兆。
- 未经代码签名的客户端被操作系统拦截并提示安全风险。
- 每次更新都需要用户手动前往网站重新下载完整安装包。

本模板采用动态零配置打包、安全签名与增量 OTA 升级方案，解决上述问题。

## 2. 跨平台打包构建

运行一键构建命令：

```bash
# 构建完整生产安装包（当前操作系统目标）
pnpm build

# 快速验证打包产物完整性与可用性
pnpm verify:dist
```

打包脚本位于 `build/electron-builder.ts`。脚本会自动读取 `package.json` 中的应用名称和版本号，无需手动编写静态 JSON 配置。

安装包生成在 `dist/` 目录下：
- Windows 系统输出：`.exe` 安装引导程序及解压绿色版目录。
- macOS 系统输出：`.dmg` 镜像文件与 `.zip` 压缩包。
- Linux 系统输出：`.AppImage` 执行文件。

## 3. 代码签名配置

配置代码签名可以防止杀毒软件误报：

### Windows 系统配置
在环境变量或 `.env.production` 中提供证书路径与密码：
- `CSC_LINK`：PFX 格式证书文件的绝对路径。
- `CSC_KEY_PASSWORD`：证书密钥密码。

### macOS 系统配置
通过苹果开发者账号申请公证：
- `APPLE_ID`：Apple 开发者账户邮箱。
- `APPLE_APP_SPECIFIC_PASSWORD`：专用 App 访问密码。
- `APPLE_TEAM_ID`：开发团队十位组织代码。

## 4. OTA 自动升级工作流

项目内置基于 `electron-updater` 的升级模块：

1. **版本检测**：主进程启动时自动向发布源查询最新版本 `latest.yml`。
2. **下载更新**：当发现新版本时，后台静默下载增量补丁并广播下载进度给渲染进程。
3. **完成安装**：用户确认后，调用 `window.api.app.quitAndInstall()` 关闭旧进程并启动新版本。

## 5. 避坑指南

- 发布正式安装包前，必须更新 `package.json` 中的 `version` 字段，且版本号必须高于线上版本。
- 保证构建机与静态发布服务器（如 GitHub Releases、S3）的连接通畅，避免 `latest.yml` 丢失导致无法检测更新。
- 打包体积过大时，检查是否有非生产依赖被错误安装到了 `dependencies` 中。前端构建依赖必须放置在 `devDependencies`。
